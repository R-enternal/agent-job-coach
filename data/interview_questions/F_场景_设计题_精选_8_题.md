# F · 场景 / 设计题（精选 8 题）

答题套路：先问清需求 → 给方案 → 讲取舍 → 说验证方式。

现有 8 类基础上扩展：只读加设备档案/传感器明细/维保历史/绿色运维数据；写操作（建工单/备件领用/维保记录）需审批；能力加文档上传入知识库、巡检图片 OCR。原则：只读直接执行、写操作审批、职责单一、description 写清触发条件。

按文档类型选切块策略；文件 hash 去重 + embedding 近似去重；按 source 删旧增量重建；加元数据过滤（型号/类型）、分区集合；向量库升级 Milvus + rerank。

输入（健康度+忙闲+历史）→ Planner 生成计划（错峰避开忙时）→ Executor 执行（查数据/建工单/登记备件）→ Replanner 检查（状态变了就调计划）→ 人工确认后下发。加分点："错峰"+ "人工确认兜底"。

先看评测集 recall——"没召回对的"还是"召回太多错的"；换 query 改写/同义词；检查 embedding 与领域匹配度；看切块是否切碎答案；加 rerank；查分数阈值/去重。每改一步评测回归。

生成 → 自评（检查清单：是否回答了问题、有无依据、数字是否可信）→ 不合格修正（补检索/换工具）→ 输出；或用 Critic Agent 评审。取舍：反思增延迟成本，只对高风险问题启用。

瓶颈：LLM 调用（慢贵有限流）→ 向量检索（Chroma 单机）→ 数据库写入（传感器数据量大）→ MemorySaver 进程内存。改造：LLM 缓存/降级/限流；向量库上 Milvus；传感器数据时序库/批量写；会话状态外部存储；Agent 无状态化水平扩容。

规则降级模型（项目已有）、本地缓存常用查询、消息队列重试、关键数据本地落盘后同步、明确提示降级模式。

工具分级：只读（自动）/写（确认）/危险（审批+双人）。工具元数据带权限等级 → 执行前过权限中间件 → 危险操作生成待审批任务，人工确认后执行，全程留痕。
