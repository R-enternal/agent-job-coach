# A · 项目开发故事（怎么开发的）

面试第一问基本是"介绍一下你项目怎么开发的"，按这条主线讲，每个节点都能展开。

一句话： 从商业计划书拆需求 → 定技术栈 → 先读参考项目 → 基础功能逐域开发 → 算法迭代成五引擎 → 双 Agent 协作开发 → 量化评测收尾。

- 需求拆解 ：把企划书技术部分落实成可执行清单——先基础功能（设备/监测/告警/工单/备件/资产），Agent 二期加；

- 技术栈 ：Python + FastAPI + MySQL + Redis + Vue3 + ECharts，后端选 Python 是因为 Agent 一定用 Python，一套语言；

- 先读参考项目再动手 ：通读一个个人项目（onecall）和一个开源项目，借鉴分层骨架（api/services/models/core/tools/agent）；

- 双 Agent 协作开发 ：Claude 写代码 + Codex 审查，设 hook——没有审查通行证不允许合并到 main，按功能模块 20 多步推进；

- 基础功能 ：设备域（设备/点位自动生成/阈值模板）→ 监测域（模拟数据源→阈值告警→趋势告警→健康度→定时任务串联）；

- 算法迭代 ：从阈值+趋势两层，升级出 Holt 预测、孤立森林、融合诊断，形成五引擎；

- Agent 模块 ：LangGraph 双智能体（对话 ReAct + 维保 Plan-Execute-Replan）、RAG 知识库、多模型、Redis 记忆、流式；

- 量化验证 ：20 题评测集（35%→100%）、15 个故障场景 100% 检出、误报率 0.4%。

讲法提示： 别背简历，讲"我遇到什么问题→怎么解决→结果是什么"。每个阶段都是面试官追问的入口。

分三层：

- 设备域 ：设备 CRUD、按类型自动生成点位（输送机→振动/温度/电流 3 点位）、阈值模板（ISO 10816 + 经验值）、点位阈值可覆盖；

- 监测域 ：先写模拟数据源（状态机：正常随机游走+故障注入，种子可复现），再做阈值告警（连续 3 次防抖）、趋势告警（滑动窗口+线性回归）、健康度（点位扣分→设备加权），最后定时任务把"采集→判定→健康度"串起来；

- 业务域 ：工单（派单/调度）、备件（低库存穿越安全线才通知）、资产台账——把"监测→诊断→处置→备件→资产"串成闭环。

健康度公式： 点位分 = 100 − 阈值(30/50) − 趋势(20) − 预测(10) − 稳定性(≤15) − 异常(≤15)；设备分 = 加权平均（振动0.6/温度0.3/电流0.1）；≥90 健康、70~89 亚健康、<70 异常。

告警优先级： 预测(扣10) < 趋势(扣20) < 阈值(扣30/50)——越早的预警扣分越轻，避免"狼来了"。

五步： ①需求拆解（问答/知识检索/维保计划/多模型四块能力，原则"不追求轻量化，追求实用性"）→ ②选型（LangGraph vs 自研，选 LangGraph：可审计状态图+流式+checkpoint；不堆 Milvus/MCP 避免过度设计）→ ③架构（双智能体：对话 ReAct + 维保 Plan-Execute-Replan；工具层独立 8 类）→ ④开发（RAG 知识库、8 工具、Redis 记忆、流式、多模型、无 Key 降级）→ ⑤踩坑与评测（孤儿消息自愈、35%→100%）。
